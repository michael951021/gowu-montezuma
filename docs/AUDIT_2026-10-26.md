## Algorithm 1/2: faithful

Outer/inner steps, halt-on-reward, child creation for survivors, all-dead rollback, lex-max (R, U) winner among

## Deviations, most likely to matter first

1. **Particle policy.** Every run so far uses `hold_random` (Remark 5.2 / Fig. 6b ablation, 8 seeds). The
   headline 98,752 number uses the learned zero-target ensemble (ε=0.2). Sec. 6.3 also calls the ablation
   "a single random *policy* sampled once per particle", which is looser than Remark 5.2's "random action".
   Untested here at GPU scale. Ensemble uses Adam, not Muon.
2. **RND learner rate.** Fixed at 8 updates / 1k agent steps (~1 sample per frame); the paper's learner is
   asynchronous and the rate is unstated. Relevant given the U collapse above.
3. **Rollback indexing.** A dead particle keeps its rollout's start node; `ancestor(node, k)` with k∈[1,3]
   goes to that node's parent or above, so the start node itself is never retried. The paper's
   "k generations prior" could mean k=1 = the start node. Ambiguous; ours rolls back one generation further.
4. **RND normaliser warm-up** uses 8 copies of the start frame, not random-agent data (Burda et al.).
   Only affects the first few million frames.
5. **Exploit guard** is a RAM surrogate for App. H's visual detector. Seeds 2/3: 0 rejections; repeated room-5
   rewards in the demos are the two legitimate 300-point doors.
